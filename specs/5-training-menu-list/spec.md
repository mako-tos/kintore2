# Training Menu List Specification

## 1. 概要

トレーニングメニューの一覧を表示し、ステータスの変更や表示順の並び替えを行う機能を提供する。
ユーザーは自分のトレーニングメニューを効率的に管理できるようになる。

## 2. 要件

### 2.1 機能要件

- **一覧表示**: 登録済みのトレーニングメニューを一覧表示する。
- **ステータス変更**: 各メニューのステータス（有効/無効など）を変更できる。
- **並び替え**: ドラッグ＆ドロップでメニューの表示順を変更できる。
- **順序の保存**: 変更した順序は永続化され、次回表示時に反映される。

### 2.2 非機能要件

- **レスポンス**: 並び替え操作は即座にUIに反映され、バックグラウンドで保存されること（楽観的UI更新）。
- **アクセシビリティ**: キーボード操作による並び替えも考慮することが望ましい（dnd-kitの標準機能で対応可能）。

## 3. データモデル

### 3.1 データベース変更

`training_menus` テーブルに `sort_order` カラムを追加する。

| Column Name  | Type    | Nullable | Default | Description                            |
| :----------- | :------ | :------- | :------ | :------------------------------------- |
| `sort_order` | INTEGER | NO       | 0       | 表示順を管理する数値。小さい順に表示。 |

### 3.2 マイグレーション

- 新しいマイグレーションファイルを作成し、`sort_order` カラムを追加する。
- 既存のレコードに対しては、`created_at` 順などで初期値を設定する。

## 4. API設計

### 4.1 トレーニングメニュー取得 (GET)

- エンドポイント: `/api/training-menus` (既存の拡張または新規)
- パラメータ: なし（認証ユーザーのデータを取得）
- レスポンス: `sort_order` の昇順でソートされたリストを返す。

### 4.2 ステータス更新 (PATCH)

- エンドポイント: `/api/training-menus/[id]`
- ボディ: `{ status: number }`
- 処理: 指定されたIDのメニューのステータスを更新する。

### 4.3 順序更新 (PUT/PATCH)

- エンドポイント: `/api/training-menus/reorder`
- ボディ: `{ items: { id: string, sortOrder: number }[] }`
- 処理: 複数のメニューの `sort_order` を一括更新する。

## 5. UI/UX設計

### 5.1 画面構成

- **TrainingMenuList**: メニュー一覧を表示するコンテナ。
- **TrainingMenuItem**: 個別のメニュー行。ドラッグハンドル、メニュー名、ステータス切替ボタンを含む。

### 5.2 ライブラリ

- ドラッグ＆ドロップ機能の実装には `@dnd-kit/core` および `@dnd-kit/sortable` を使用する。
- これらは軽量でアクセシビリティに優れ、React/Next.js との親和性が高い。

### 5.3 インタラクション

1. ユーザーがドラッグハンドルを掴んで移動させる。
2. ドロップした時点でフロントエンドのリスト順序を更新（即時反映）。
3. 非同期でAPIを呼び出し、順序を保存する。
4. 保存に失敗した場合はエラーを表示し、元の順序に戻す（オプション）。

## 6. 実装ステップ

1. **DBマイグレーション**: `sort_order` カラムの追加。
2. **バックエンド実装**:
   - `TrainingMenu` 型定義の更新。
   - リポジトリ層での `sort_order` 対応（取得時のソート、更新処理）。
   - APIエンドポイントの実装 (`reorder` APIなど)。
3. **フロントエンド実装**:
   - `@dnd-kit` の導入。
   - `TrainingMenuList` コンポーネントの実装。
   - ドラッグ＆ドロップロジックの組み込み。
   - API連携。

## 7. テスト計画

- **単体テスト**: コンポーネントのレンダリング、ステータス変更ロジック。
- **統合テスト**: APIを通じた順序保存の検証。
